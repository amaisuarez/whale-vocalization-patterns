# Journal 02 · Tempo across the repertoire

**Date:** 2026-09-24
**Notebook:** `03_tempo_across_repertoire.ipynb` · **New module:** `src/whalecodas/tempo.py`

## Question

`1+1+3` has three tempo classes (journal 01). Is that specific to `1+1+3`, or is tempo a shared dimension of the repertoire, with discrete classes that line up across coda types?

## Plan vs what actually happened

**Plan:** group expert types into rhythm families (same shape, different speed), then look for tempo classes inside each family.

**What happened:** the grouping step failed. A classifier that sees only rhythm (no duration) separates even the most similar-looking pairs well above chance (`5R2` vs `5R3`: 0.70; `4R1` vs `4R2`: 0.78). Rhythm and tempo interact: shape changes slightly with speed. Any merging threshold would have been arbitrary, so I reformulated: test each expert type separately, then compare centres across types.

## Corrections to my own method

1. **BIC over-splits.** It fitted 2–3 Gaussians to `5R1`, `4D`, `8i` and `3D`, but the components overlap almost completely (Ashman's D < 1). These are asymmetric single peaks, not classes. Without checking D, I would have reported four false discoveries.
2. **Codas are not independent observations.** Codas from the same unit on the same day come from the same conversation. The coda-level bootstrap in journal 01 therefore overstated certainty. I now resample **whole sessions** (unit × day, 103 sessions in total).
   - Effect on the main result: `1+1+3` is still multimodal in 100% of session resamples, but k = 3 in ~90% (not 100% as in journal 01). Still robust, just honestly measured.

## Results

| claim | status |
|---|---|
| `1+1+3` has 3 tempo classes (~0.81 / 1.05 / 1.28 s) | **robust** |
| Rhythm and tempo are independent | **rejected** |
| Tempo splits in `5R1`, `4D`, `8i`, `3D` | **artefacts** |
| `i` types (`6i`, `7i`, `9i`) are tempo-multimodal | **candidate**: k unstable, some tiny modes |
| `7D1` shares two tempo classes with `1+1+3` | **weak**: overlapping CIs, but 82% unit F, mostly 3 days |
| Whole repertoire shares a small tempo grid | **not testable** with one robust type |
| Tempo co-varies across types within a session | **not supported** (r ≈ 0.15, p ≈ 0.37, 40 sessions) |

## Most interesting dead end

On one day unit F's `7D1` and `1+1+3` codas were both mostly slow; on another, both leaned fast. That suggested a "conversation tempo". Tested across 40 sessions: nothing. Tested type by type: two nominal hits with opposite signs, none surviving Bonferroni. A good example of how an anecdote from a table can look like a pattern.

## Observation to keep in mind (not a claim)

The slowest types (`8R`, the slow mode of `7D1`, the slow class of `1+1+3`) all peak around 1.2–1.3 s, across 5, 7 and 8 clicks.

## Next session

Model how rhythm changes as tempo changes. When a coda slows down, do all ICIs stretch equally, or do some change more? This follows directly from the rejected independence assumption and connects to what Sharma et al. call *rubato*.
